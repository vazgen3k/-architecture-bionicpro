Для унификации доступа в системе BionicPRO предлагается использовать централизованный Auth Broker на базе Keycloak. Keycloak выступает не как основное хранилище персональных данных пользователей, а как брокер идентификации между системами BionicPRO и внешними удостоверяющими службами, расположенными в странах присутствия компании.
Для каждой страны подключается отдельный внешний Identity Provider / User Directory. В нём локально хранятся учётные данные пользователей, а также персональная информация, если этого требует законодательство конкретной страны. Keycloak получает от внешнего IdP только необходимые идентификационные атрибуты и связывает внешнюю учётную запись с внутренним техническим идентификатором пользователя BionicPRO.
Для защиты access- и refresh-токенов используется паттерн Backend for Frontend / Session Gateway. Android-приложение и интернет-магазин не получают токены, выданные внешним IdP или Keycloak. После успешной аутентификации Auth BFF получает токены от Keycloak на backend-стороне, создаёт серверную сессию и возвращает клиенту только защищённую сессионную cookie с флагами HttpOnly, Secure и SameSite.
Все refresh-токены и данные серверных сессий хранятся в Auth DB, например Redis. Клиентские приложения обращаются к API только через сессионный механизм. API проверяет сессию пользователя через Auth BFF или получает от него внутренний короткоживущий токен с минимальным набором claims.
Такое решение исключает передачу access- и refresh-токенов во фронтенд, позволяет централизованно управлять аутентификацией и поддерживает подключение разных внешних удостоверяющих служб для разных стран.
